// CORE DIFFERENTIATION
为什么不用 ADB 和无障碍

市场上几乎所有同类产品都依赖 ADB 或无障碍服务——这是我们认为根本错误的方向。

✗  传统方案的困境
🔌
ADB 依赖 · 必须连线
每台手机需开启开发者模式、配对 USB 或同局域网。手机离线或重启后连接即断，无法真正做到远程无人值守。服务器与设备必须保持持续网络通道，部署成本极高。
🚫
无障碍服务 · 脆弱且可被检测
用户必须手动进入系统设置逐一授权。系统低内存、省电模式会强制杀掉无障碍服务。更致命的是，微信、支付宝、抖音等主流 App 主动检测无障碍并拒绝运行或弹出警告，导致脚本在最需要的场景下完全失效。
🐢
性能差 · 延迟高
ADB 命令通过 shell 解析再下发，无障碍事件经过多层转发，两种方式的操作延迟均在 100–500ms 级别，批量并发时问题更严重。
✓  NexusFlow 的方式 · 系统级注入
⚡
运行在 system_process · 无需任何授权
基于 LSPosed / Riru 将代码注入 Android 系统进程本身。一次刷入 Magisk 模块，永久生效，重启后自动恢复，无需用户做任何操作。
📡
无需连线 · 只需联网
手机只需接入任意网络（4G / Wi-Fi），通过 MQTT 接收服务器指令，与服务器距离、是否在同一局域网完全无关。支持 FRPC 内网穿透，任何网络环境均可工作。
🥷
App 无法感知 · 操作来自系统层
直接调用 InputManager.injectInputEvent()，操作事件的来源与系统触屏完全一致，任何应用层的检测手段均无法区分真实触摸与 NexusFlow 注入的事件。
⚡
系统级权限
基于 LSPosed 注入 system_process，直接调用 InputManager.injectInputEvent()，无需无障碍授权，无需用户确认
🧠
AI 魔法生成
自然语言一句话生成可编辑 JS 脚本，Claude / GPT-4V 视觉理解屏幕，运行时 AI 自动处理异常弹框
📜
Auto.js 兼容
内置 Rhino JS 引擎，55% API 直接兼容，原 Auto.js 开发者零学习成本迁移，存量脚本可直接复用
🌐
批量云控
MQTT 批量下发脚本，WebSocket 实时监控执行状态，一键同时操控百台设备完成相同业务流程

// CORE FEATURES
四层能力

从基础脚本执行到完全视觉驱动的 AI Agent，按需选择复杂度

PHASE 1 · FOUNDATION
脚本引擎层
Script Engine · Rhino JS · Auto.js 兼容
内嵌 Mozilla Rhino JS 引擎（Auto.js 同款），提供与 Auto.js 55% 以上 API 直接兼容的执行环境。脚本以 JSON 形式通过 MQTT 下发到设备，由运行在 system_process 的 daemon 直接执行——整个过程不需要安装任何额外 App，断网仍可运行主流程。

每条操作直接调用系统底层：tap() 对应 InputManager 注入，captureScreen() 对应系统截图接口，原 Auto.js 开发者迁移成本极低。
Rhino 1.7.xMQTT 脚本下发 tap / swipe / longPresscaptureScreen http / files / threadsAuto.js 兼容
PHASE 2 · AI GENERATION
AI 魔法生成层
自然语言 → 可编辑 JS 脚本 · Claude Vision / GPT-4V
运营人员无需编程，用一句话描述要做的事（例如"进入抖音发布视频，文案：{{caption}}"），服务器截取设备屏幕，调用视觉大模型分析 UI 结构，30 秒内生成完整可执行脚本。

生成结果在 Monaco 编辑器中展示，用户可直接修改调整后再下发。不确定位置的按钮自动用 ai.findElement() 代替硬编码坐标，脚本天然具备 UI 变化容错能力。支持参数化模板：文案、链接、账号等内容作为变量，批量执行时每台设备传入不同参数。
Claude VisionGPT-4V Monaco 编辑器参数化模板 可二次编辑AI 系统提示词
PHASE 3 · RUNTIME AI
运行时 AI 兜底层
执行中遇到意外 → AI 实时分析修复 → 自动继续
脚本按预定流程执行，遇到预期外的弹框、UI 变化、页面跳转时，不报错退出，而是自动触发 AI 介入：设备截图 + 控件树同步上报服务器，LLM 分析当前状态并返回应对代码，设备执行后回到主流程继续。

后台常驻弹窗守护线程，优先用规则匹配"关闭/取消/我知道了"等常见弹框（毫秒级），规则无法处理时才调用 AI（成本控制）。Happy Path 全程零 AI 调用，只在真正需要时才花费 LLM token。
ai.fix()ai.findElement() ai.findAndTap()弹窗守护线程 IAccessibilityManager自动恢复主流程
PHASE 4 · VISION AGENT
Vision Agent 模式
纯自然语言驱动 · 无需预先编写任何脚本
终极模式：用户只说目标，AI 自主决策每一步操作。实时截图 → LLM 决策（"当前是什么界面？下一步做什么？"）→ 执行 → 截图，循环直到目标完成。

适用于高度动态 UI、探索性任务、内容审核/智能回复等无法预先编写脚本的场景。也可作为运行时兜底的最后一道防线：当 Phase 3 的 AI 修复仍无法处理时，切换到 Agent 模式接管整个流程。

// 后台弹窗守护线程（自动开启）
threads.start(function() {
  while (SCRIPT_RUNNING) {
    var ui = getUITree();

    // 规则优先（快）
    var btn = ui.findByText([
      "关闭", "×", "取消", "我知道了", "拒绝"
    ]);
    if (btn && isPopup(btn)) {
      tap(btn.x, btn.y);
      sleep(500);
      continue;
    }
    // 无规则命中时 AI 接管
    sleep(1500);
  }
});
